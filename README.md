# riso-screen

给 Canvas 2D 的孔版印刷（risograph）网点引擎。三件事：**分色网点角度**、**套印偏移**、**逐帧 boil**。

单文件、无依赖、无构建。160 行。

**[▶ 在线 demo](https://qiuqiunb666.github.io/riso-screen/)** — 新旧对比、连续色阶、玫瑰花结放大、tile 边界放大，以及 56 项自检。

---

## 解决什么问题

用 Canvas 画 riso 风格，通常是搞一个点阵 tile 然后 `createPattern(tile,'repeat')`。问题是所有色版共用同一套网格、同一个角度，于是：

- 三个版的点互相压在一起，叠印出来是死板的棋盘格，不是印刷品
- 浓淡只能靠预生成几个固定 tile，做不出连续色阶
- 逐帧动画里网点纹丝不动，或者一动就闪成噪点

这个模块把这三条一起解决。

## 三件事

### 1. 网点角度

每个色版一个角度，两两相差 30°（mod 90）。方形点阵旋转 90° 回到自身，所以可用角度空间只有 `[0°,90°)`，`90/3 = 30` —— **最多只能安排三个版互成 30°**。三墨正好填满，不多不少。

```js
var SCREEN = { warm: 15, cool: 75, dark: 45 };
```

分配依据是**相对亮度，不是色相**：最暗的墨拿 45°，中间拿 75°，最亮拿 15°。两条独立理由——人眼对 ±45° 斜向光栅的对比敏感度显著低于水平/垂直方向（oblique effect），而最暗的墨网点结构最该被藏起来。

为什么是 30°：等节距双光栅的拍频周期 = `p / (2·sin(Δθ/2))`。

| Δθ | 摩尔纹周期 |
|---|---|
| 5° | 11.5 格 — 大花，肉眼直看 |
| 15° | 3.83 格 — 看得见的格纹 |
| **30°** | **1.93 格 — 读作玫瑰花纹理** |

别改成 0/30/60：数学上等价，但 0° 与像素栅格硬混叠，会出"纱窗"。

角度通过 `pattern.setTransform` 施加，顺序是 `T·R·S`：

```js
p.setTransform(new DOMMatrix().rotateSelf(SCREEN[key]).scaleSelf(1 / PAT_K));
```

`rotateSelf` 的参数单位是**度**不是弧度。

### 2. 连续色阶

点面积正比于浓度，所以 `r = cell·√(t/π)`，单格不重叠时覆盖率恰好等于 `t`。

`t > 0.5` 翻转成「填满 + `destination-out` 挖白点」，半径用 `(1-t)`。**翻转点在 0.5 不是因为相切**——相切其实发生在 `t = π/4 ≈ 0.785`。真正的理由是：翻转后两个分支的半径都 ≤ `cell·√(0.5/π) = 0.399·cell`，直径永远小于一格，点既不相切也不越过 tile 边界，旋转平铺才无缝、低调区才敢抖位置。

另外不翻转的话高调区根本出不了实地：圆在方格阵上重叠后，`t=1` 也只能盖住 **90.95%**。

**tile 边界是两个分支唯一不对称的地方**，这是全模块最容易写错的一处：

- 低调区点心在**格中心**，位置抖 ±0.45px（按格内余量自动收窄，保证碰不到边界）
- 高调区挖白点点心在**格点上**（含 0 和 `PAT_CELLS` 两端），**位置一个像素都不能抖**——一抖 tile 两侧边界就对不上，平铺后沿网点角度排出斜接缝
- 两端那对半点的**半径也必须相同**，所以半径倍率按格索引查表，`x=0` 和 `x=PAT_CELLS` 取同一个值

### 3. 逐帧 boil

三套 tile 轮换（`variant = boil % 3`），加上套印偏移的逐帧微抖。

**网点 boil 必须比线条 boil 慢一个量级。** 线条可以每个作画帧都抖（手抖），网点跟着一帧一换会闪成噪点爬行。默认每 8 个输出帧换一版 = 3Hz，对应 12fps 作画下的 4:1。

**最关键的一条：半径倍率表的随机流里不能带 variant。**

```js
var rs = mulberry32(seed);                    // 尺寸：不随 variant 也不随 level 变
var rp = mulberry32(seed + variant * 17);     // 位置：随 variant 变
```

带了的话三个版的总覆盖率不同，平涂区会在 3Hz 上整块明暗跳。**位置变化眼睛读成「工艺」，密度变化读成「闪」。** 实测三版覆盖率峰峰 0.024%~0.048%；合流的写法是 3.05%，差两个数量级。

同理种子里也不能带 `level`：64 个样本的覆盖率噪声（±1%）和档距（1/60 = 1.67%）同量级，带了会让相邻档实际浓度差到 2.7 倍，加到 60 档就白加了。

套印偏移里**基准版要钉死不抖**。小数 `drawImage` 偏移会让整层重采样锐度随版本阶跃，那是比网点本身大得多的闪源。

## 接进去

模块依赖宿主引擎已有的四样：`INK`（墨色表）、`L`（各墨的离屏图层 ctx）、`OFFSET`（各版套印偏移）、`mulberry32`。`index.html` 里有一份 20 行的最小底座可以照抄。

```js
// 1. 整段引入 riso-screen.js（它自己声明 var TONE = {}）
// 2. 启动时调一次
initTones();
// 3. 每帧第一句
function paintFrame(f){
  setBoil(f);
  // ...绘制...
}
```

拿 pattern 直接当 `fillStyle` 用：

```js
ctx.fillStyle = TONE.dark;            // 五个老名字：warm / cool / dark / warmL / coolL
ctx.fillStyle = TONE.at('cool', .42); // 任意浓度，60 档
```

`setBoil(f, hold)` 的第二参传任意值（比如镜头序号）就冻结成该值对应的版本——「一镜一纸」，长静止镜头或结尾定格用它，线条 boil 留着，一层活着就够了。

## 可调常数

| 常数 | 默认 | 说明 |
|---|---|---|
| `CELLW` | `5.25` | 网点格宽（最终 px）。**别低于 4**：3px 网点会被 h.264 嚼成蚊式噪声，静帧好看 mp4 糊 |
| `PAT_K` | `5` | 超采样倍数。低于 4 旋转会把点糊成噪点 |
| `TONE_LEVELS` | `60` | 色阶级数 |
| `BOIL_EVERY` | `8` | 每几个输出帧换一版 |
| `BOIL` | `true` | 总开关。`false` = 冻成 variant 0 + 零套印抖动 |
| `INK_MAX` | `.92` | 单墨浓度上限。满墨会让纸消失、三墨糊成死黑；要实地请直接用 `INK[k]` |

**堆墨要留意**，multiply 叠印下比纸上更要留意：

```
a=(0.9,0.9,0.9)  → 露纸 0.10%  总墨 270%  纸消失，三墨身份消失，糊成死黑
a=(0.85,0.3,0.2) → 露纸 8.4%   总墨 135%  纸还在呼吸   ← 暗部推荐配方
```

暗部让最深的墨单独扛，另外两墨压到 ≤0.5。

## 自检

`riso-selfcheck.js` 是 headless 版（`risoSelfCheck()` 或 `window.__risoCheck`），适合塞进渲染管线；`index.html` 把它和一套视觉/数值检查一起跑，共 **54 项**。覆盖的都是会静默失效的地方：

- pattern 缓存 key 漏了 `variant` → boil 假死，画面完全不抖但代码看着是对的
- 三个 variant 覆盖率不一致 → 平涂区 3Hz 闪
- tile 生成偷吃了宿主的全局随机流 → 「这帧用到哪几档 tone」会改变手绘线的随机序列，整片逐帧漂移
- 低调区点越过格边界 → 旋转平铺出斜接缝
- 色阶步长不均 → 渐变变台阶

## 代价

在 1080×1080 / 626 帧的逐帧导出上实测：**渲染时间约 +82%**；网点是高频内容，**mp4 体积 ×2.6~2.9**（crf23）。出片时把 crf 压到 ≤16 或加 `-tune grain`，否则网点会被编码器嚼掉。

## 来源

技术路线来自 Kevin Ngo（[@kevin_t_ngo](https://x.com/kevin_t_ngo)）的 [a small light, room by room](https://a-small-light-three.vercel.app)——一个 1.1MB 单文件、25 间等距房间的 Canvas 作品。`patternCanvas` / `inkPattern` 的结构和大部分常数照抄自它。

移植到分层 multiply 架构时有三处不能照搬，都在代码注释里标了：

1. **套印偏移不进 pattern**。原版只有一张 canvas，版错位没处放只能塞进 `translateSelf`。分层架构里 `compose()` 的 `drawImage(layer, OFFSET)` 整版平移才是真印刷——整块版错位，线条跟着一起错。塞进 pattern 会叠两遍，而且线条不会动。
2. **角度分配按亮度重排**。原版按色相硬套 CMYK 槽位，按亮度看是接反的，只因为它有第四个墨顶掉 0° 才没暴露。
3. **缺墨斑点要环绕**。原版斑点起点可以逼近 tile 边长，跨边界的方块被裁掉而不是 wrap，于是每个 tile 右/下约 1.8px 带里挖墨量系统偏低，平铺后是一张按网点角度斜排的极淡亮线格。这里每个斑点画 4 份。
